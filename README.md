# Android Screenshot Tool 1.1.0

Консольная утилита для Windows и Linux, которая делает снимки экрана Android через `adb`.

## Возможности

- единый список USB- и сетевых устройств из `adb devices -l`;
- выбор устройства стрелками `↑/↓`, `Enter` или цифрами;
- выбранное устройство постоянно видно в главном меню;
- при открытии списка устройств курсор стоит на выбранном сейчас устройстве;
- последнее выбранное устройство сохраняется между запусками и автоматически восстанавливается, если доступно;
- главное меню сохраняет ранее выбранную строку, поэтому повторный снимок можно делать одним Enter;
- если устройство ещё не выбрано, команда снимка сначала открывает выбор устройства;
- PNG без перекодирования;
- JPG с качеством 99, без цветовой субдискретизации (`subsampling=0`);
- имя файла: `Модель_YYYY-MM-DD_HH-MM-SS.png|jpg`;
- снимки сохраняются в подкаталог Screenshots текущей рабочей папки;
- видео сохраняются в подкаталог Videos текущей рабочей папки;
- каталоги Screenshots и Videos исключены из Git и не попадают в публичный репозиторий;
- запись видео: MP4/H.264, yuv420p, аварийно-восстанавливаемый fragmented MP4 во время записи и faststart после штатной остановки;
- итоговый FPS видео: 6, 12, 24, 30, 45 или 60;
- микрофон Android выключен по умолчанию и включается только на совместимых прошивках с доступным tinycap;
- перед снимком состояние выбранного устройства проверяется повторно;
- `offline` и `unauthorized` показываются в списке, но не выбираются как рабочие;
- при запуске исходного `.py` Pillow для JPG устанавливается автоматически, если отсутствует;
- EXE и DEB собираются как автономные бинарники с Pillow внутри.

## Требования

- `adb` заранее установлен и доступен в `PATH`;
- для запуска исходного файла: Python 3;
- для сетевого Android устройство должно быть доступно для `adb connect IP:PORT`; последнее сетевое устройство программа пытается переподключить автоматически;
- для записи видео нужен FFmpeg; программа пытается установить его автоматически там, где это возможно.

## Запуск исходника

Windows:

```bat
python android_screenshot_tool.py
```

или двойным щелчком по `run_windows.bat`.

Linux:

```bash
python3 android_screenshot_tool.py
```

или:

```bash
./run_linux.sh
```

## Проверка версии

```bash
python android_screenshot_tool.py --version
```

Windows EXE:

```bat
AndroidScreenshotTool-v1.1.0-windows-x64.exe --version
```

После установки DEB:

```bash
android-screenshot-tool --version
```

Команда версии не требует подключённого Android и не запускает ADB.

## Главное меню

1. Сменить устройство.
2. Сделать снимок экрана.
3. Записать видео.
4. Формат снимка: PNG/JPG.
5. Настройки видео.
0. Выйти.

## Видео

Для записи видео нужен FFmpeg с кодировщиком libx264. На Windows программа при необходимости пытается установить пакет Gyan.FFmpeg через WinGet; Debian-пакет зависит от системного пакета ffmpeg.

Настройка FPS задаёт частоту кадров итогового MP4. Стандартный Android screenrecord не предоставляет переносимого параметра произвольного FPS, поэтому FFmpeg отбрасывает или повторяет кадры до выбранного значения. Если Android реально отдаёт, например, 30 уникальных кадров/с, режим 60 FPS не создаст дополнительных деталей.

Во время записи создаётся файл Videos/Model_YYYY-MM-DD_HH-MM-SS.recording.mp4 как fragmented MP4 с короткими фрагментами. При штатной остановке он перепаковывается без повторного кодирования в обычный MP4 с moov в начале (faststart). Это повышает шанс сохранить уже записанную часть при аварийном завершении, хотя абсолютной гарантии при отказе носителя или внезапном отключении питания нет.

Официальный adb shell screenrecord звук не записывает. Режим микрофона использует tinycap только там, где прошивка предоставляет эту программу и разрешает ADB-shell доступ к входному PCM. Если проверка не проходит, программа оставляет запись без звука. Универсальный микрофон на произвольном Android потребовал бы отдельного Android-компонента с разрешением RECORD_AUDIO.

Пользовательские настройки находятся вне репозитория: на Windows — %APPDATA%\AndroidScreenshotTool\settings.json, на Linux — ~/.config/android-screenshot-tool/settings.json (или XDG_CONFIG_HOME).

## Обновление

Windows:

```bat
update.bat
```

Linux:

```bash
./update.sh
```

Обновляющий сценарий останавливается при наличии локальных незакоммиченных изменений, выполняет только fast-forward pull, проверяет синтаксис Python, версию программы и наличие ADB. update.bat запускает рабочую часть из временной копии, поэтому способен безопасно обновить сам себя.

## Сборка EXE на Windows

Запустить:

```bat
build_exe.bat
```

Сценарий сам:

1. создаёт `.venv-build-win`;
2. обновляет `pip`;
3. устанавливает Pillow и PyInstaller;
4. собирает `dist\AndroidScreenshotTool.exe`.

## Сборка DEB на Debian/Ubuntu

Запустить:

```bash
chmod +x build_deb.sh
./build_deb.sh
```

Сценарий сам устанавливает недостающие системные средства сборки через `apt-get` (с `sudo`, если он доступен), создаёт `.venv-build-linux`, загружает Pillow и PyInstaller, собирает автономный Linux-бинарник и затем `.deb` в каталоге `dist/`.

Установка готового пакета:

```bash
sudo apt install ./dist/android-screenshot-tool_1.1.0_*.deb
```

После установки запуск:

```bash
android-screenshot-tool
```

## Ограничения

- Утилита не включает Android Platform Tools внутрь EXE/DEB и не меняет настройки ADB: по условию задачи `adb` уже должен быть доступен в `PATH`.
- `build_exe.bat` нужно запускать именно в Windows: PyInstaller собирает исполняемый файл для текущей ОС.
- `build_deb.sh` собирает пакет для архитектуры Linux-машины, на которой он запущен.

## Готовые выпуски

Теги вида `v*` запускают GitHub Actions, который собирает Windows EXE, Debian DEB, чистый ZIP исходников через `git archive`, файл `SHA256SUMS.txt` и публикует их в GitHub Releases.

`Screenshots/`, `Videos/`, кэши Python, виртуальные окружения и результаты локальной сборки в архив исходников не попадают.
